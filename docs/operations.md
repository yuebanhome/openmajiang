# 运维权限与故障处理

管理员使用独立 `operator` 角色。公开注册只能创建 `user`，接口不接受自选角色。先通过正常注册、邮箱验证创建操作员账号，再在受控部署终端执行：

```sh
docker compose --env-file deploy/.env -f deploy/compose.yaml exec app \
  openmajiang admin grant --email operator@example.com --reason '首次部署管理员授权'
```

命令必须连接目标环境的数据库；只接受已验证、正常状态的现存账号，不创建初始密码，也不打印密码、会话或密钥。授权与 `deployment_cli/operator_grant` 审计在同一事务内提交。正常退出并重新登录后确认权限；不要通过修改公开注册请求取得运维角色。

## 可执行操作

所有管理读接口都要求已验证、正常状态的 operator。所有写接口同时要求会话、同源 `Origin` 和 `X-CSRF-Token`，并在事务内重新确认操作员及其会话仍有效。原因是 2–200 字的单行文本，填写业务原因，不粘贴密码、完整邮件链接、Bot token 或牌墙。

| 接口 | 内容 | 行为 |
| --- | --- | --- |
| `GET /v1/admin/status` | 维护状态、活动比赛/等待房间/排队数量、邮件积压/失败数量 | 只返回聚合运维数据 |
| `POST /v1/admin/maintenance` | `{enabled,message,reason}` | 停止新建、入座、排队匹配与新开局；已开始的比赛继续执行 |
| `POST /v1/admin/users/:id/status` | `{status:"restricted"或"active",reason}` | 限制时撤销真人会话、Bot 凭据/会话和排队，当前手结束后退出；恢复资格不恢复旧凭据 |
| `POST /v1/admin/bots/:id/disable` | `{reason}` | 设置独立的管理员停用标记并撤销凭据/会话；所有者不能用 enabled=true 绕过 |
| `POST /v1/admin/bots/:id/restore` | `{reason}` | 移除管理员停用，所有者自行启用并创建新密钥；不恢复旧密钥 |
| `POST /v1/admin/rulesets/:id/versions/:version/status` | `{enabled,reason}` | 仅控制新比赛准入，已有比赛保持锁定的规则版本 |
| `POST /v1/admin/matches/:id/abort` | `{reason}` | 中止活动故障桌，保留已完成得分和原有牌局状态；未完成手不判输赢、不改分 |
| `GET /v1/admin/audit?before=<id>` | 每页最多 100 条 | 操作者、动作、目标、原因、结果、时间；按返回 next_before 翻页 |
| `GET /v1/public/status` | 无需登录 | 仅公开维护状态与公告；不公开内部操作原因 |

维护和规则开关使用数据库事务锁与准入共享锁同步；收到维护成功响应后，新准入不能越过开关。故障桌中止标记为 `aborted_by_operator`，不计成正常完赛排名。普通发布先维护、等当前比赛完成、确认活动数归零，再按 [部署手册](deployment.md) 备份升级。

运维接口不提供全知观战、读取暗手、读取牌墙、导出用户令牌或任意改分。公开观战仍只显示弃牌。账号限制不会改写已发生的合法得分；当前手的默认动作与退出由正常牌局超时/手间规则处理。

## 检查与响应

- `/health/live` 检查进程存活，`/health/ready` 检查服务就绪；健康响应不回显配置和数据库地址。`openmajiang healthcheck` 使用就绪检查。
- 邮件积压升高时检查 SMTP 网络、TLS、发件人授权与投递情况。`sent` 只表示 SMTP 接受。失败任务不返回邮件正文或链接；修复后由用户重新申请，遵守重发冷却。更换邮件加密密钥会使既存待发邮件无法解密。
- 多桌同时超时或数据库连接异常时先维护，保留日志与镜像 digest，修复依赖后观察恢复结果。平台中断不能记成正常输赢，不通过手工更新比分修复。
- 撤销或限制账号后，旧真人连接和 Bot 凭据必须不能继续提交动作。恢复账号不自动恢复旧设备；重新登录并按需要创建新 Bot 密钥。
- 数据库备份应定期在隔离环境恢复，验证注册、比赛历史和版本兼容；只有备份文件存在不算恢复演练完成。

审计只记录管理动作及必要标识，不存储原始请求体、邮箱验证 token、密钥和私牌。数据库故障时不能保证写入新的审计记录，因此管理变更与成功审计采用同事务：审计写入失败会使变更回滚。应用日志保留有限滚动，长期审计和备份的访问由部署方控制。
