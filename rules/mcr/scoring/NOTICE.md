# MCR 算番来源与规则口径

本目录的 C++ 实现来自 [summerinsects/mahjong-algorithm](https://github.com/summerinsects/mahjong-algorithm)，固定提交 `44a178af08bf11f82a8993fddbe2fe8876ddd8f3`（2026-03-30）。作者 Jeff Wang，MIT 许可证。完整授权文本保存在 `vendor/mahjong-algorithm/LICENSE`，原文件版权头保持原样，包括原作者写明的年份。这里不复制或引用 Botzone 裁判代码的授权。

`UPSTREAM.json` 记录每个原文件及本地文件的 SHA-256，`wmo2014.patch` 列出全部上游算法修改。Go API、C ABI 桥接、WMO 适配和新测试是 OpenMajiang 的代码。`testdata/upstream_hands.json` 中的牌例源自同一 MIT 项目的 `unit_test.cpp`，保留原行号以便核对。

## 规则来源

规则基线是文档锁定的 WMO《麻将竞赛规则》2014 年第 2 版中文条款，审阅副本：

- [Greenbook2021_Chinese-EN.pdf](https://mahjongclublausanne.ch/wp-content/uploads/2024/03/Greenbook2021_Chinese-EN.pdf)
- SHA-256：`77220856f7d02a9d108cb4046038102ac46a9271ed2baf48b383cb13691be01c`
- 官方分发地址：[MCR2021.pdf](https://www.mindmahjong.com/adobe/MCR2021.pdf)。不因文件名含 2021 就视为 2021 修订；本次适配以已核 hash 的副本为准。
- 以下页码是书中中文印刷页码，非 PDF 页索引。

该版本与常见 Botzone/MIL 库默认值存在差异。应用不能把一个算番库的默认规则直接标为选定的 WMO 版本。

## 相对上游的完整变更

| 项目 | 上游默认 | 本目录规则 | 依据 |
|---|---|---|---|
| 双暗杠 | 6 分 | 8 分；官方编号 48 | 第 40 页，番种 48 |
| 一明杠一暗杠 | 自定义番种“明暗杠”5 分 | 双明杠 4 + 暗杠 2，共 6；不增加第 82 番 | 第 43 页，番种 57 |
| 九莲、连七对、十三幺、七对、七星不靠、全不靠自摸 | 自摸 1 分 | 不求人 4 分；不重复自摸 | 第 26、27、31、36 页 |
| 四暗刻自摸 | 将不求人降为自摸 1 分 | 保留不求人 4 分 | 第 28 页，番种 12 |
| 绿一色 + 混一色 | 排除混一色 | 允许加计 | 第 25 页，番种 3 的定义及牌例 |
| 清幺九 + 双同刻 | 排除双同刻 | 允许加计，包括两个双同刻 | 第 27 页，番种 8 的牌例 |
| 组合龙龙身的边、坎、钓 | 启用 MIL 特别解释 | 关闭该扩展；仅按剩余面子及唯一和张判定 | 第 36 页及第 48 页；组合龙龙身不视为普通顺子 |
| 三杠、四杠中的暗杠加计 | 不另加暗杠类番 | 使用下面独立命名的 `om-mcr-1-kong-additions` 裁决 | 第 26、30 页允许暗杠加计；重复累计的细节需要独立规则复核 |

桥接层把上游第 53 项双暗杠映射到官方第 48 项，并平移官方 49–53 项；对外 `Fan.ID` 始终是所选书的 1–81 编号。`Points` 是单项分值，`Count` 是次数。Go JSON 字段 `non_flower` 单列非花分；是否允许和牌由引擎检查 `non_flower >= 8`。花牌不使一个 7 分和型达到起和门槛。

另外两项代码改动不改变选定规则分值：

- 九莲判断先拒绝字牌和张。上游分支在“四张相同字牌”的未成和输入中可能先访问该花色不存在的第九张，新增守卫防止越界读取。
- `calculate_fan` 增加可选的 `calculation_details_t` 输出，直接在最大分选中或同分取舍位置记录真实候选牌组；组合龙也记录匹配的九张和其余面子。不会在算分完成后另找一个任意拆分。

对外 `winning_form` / `decomposition` 展示已选最高番和型，特殊七对、十三幺、不靠、九莲按所选特殊型展开。`explanations` 对每个已计番标注计算来源，列出已核对的不计关系；`explanation_coverage` 固定说明覆盖的是“所选最高分和型及有依据的不计关系”，不声称包含每个失败候选的完整搜索轨迹。`Group.Concealed` 表示牌组在立牌中或暗杠声明的状态，不能据此直接断言点和完成的刻子必然获得暗刻番。

### `om-mcr-1-kong-additions` 裁决条款

选定中文原文允许三杠、四杠加计暗杠，但未在这些条款列出所有明暗数量的组合分表。本实现明确选择：

1. 三杠或四杠保留其本番；暗杠系列只取一个最高奖项：一副暗杠加 2 分，两副或以上暗杠加双暗杠 8 分。
2. 不把三副暗杠再拆成“双暗杠 + 暗杠”，不把四副暗杠重复计两次双暗杠。
3. 三暗刻、四暗刻继续按真实暗刻数量判断和加计；与双暗杠必然重复的双暗刻不计。一个暗杠加一个普通暗刻仍可计双暗刻。
4. 明杠不再重复计入三杠、四杠。

此条款是 OpenMajiang 具名裁决，**待独立规则复核，不宣称已经得到官方专门确认**。将来更改须更换规则版本，不能重算旧牌谱。测试 `TestOMMCR1ConcealedKongAdjudication` 覆盖明暗数量组合及三暗刻、四暗刻兼容性。

## 测试与剩余验收范围

- 81 个独立正例分别命中全部官方番种；这些是覆盖测试，不是“所有组合都已验证”的证明。
- 对上述 WMO 差异、7/8 非花分与 0/1/2/8 花牌、风牌复合、杠抢与绝张、七对四张同牌、多番排除关系另做断言。
- 导入 191 个上游历史回归牌例，验证可评估、计分总和一致。它们不是独立 WMO 计分标准答案。上游 23 个带 `WIN_FLAG_INITIAL` 的天地人和相关例不导入；本 API 不接受该扩展，原始完整 `unit_test.cpp` 保留在 vendor 中。
- 81 种牌例并发重复计算和手牌顺序不变性测试；Go race 测试通过。Go race 不能替代对 C++ 的静态分析或原生线程检测。
- 对全部 81 例检查最佳拆分牌张守恒，对同时可以拆成七对和普通型的高分牌例检查真正取最大番的顺子分解；字牌误入九莲分支的边界另有回归测试。
- 公开 `Shanten` 使用普通型、七对、十三幺、全不靠、组合龙的最小向听；已副露时按和型限制关闭不成立的特殊型。向听 0 只代表形状听牌，Bot 仍须用 `Evaluate` 检查起和分。

剩余独立验收包括上述杠裁决，以及所选中文条款和英文译文在特殊七对与牌性番叠加中的文字差异。不要仅因为库拥有 81 个名称、通过 81 个正例就将“完整赛事规则认证”标成已完成；需要补充独立裁判确认的争议牌例。这不影响已实现的计算接口及其固定、可复现的行为。

## 编译

要求 `CGO_ENABLED=1` 和 C++11 编译器；Linux 运行时需要 `libstdc++`。Docker 构建阶段使用 `g++`，运行镜像安装 `libstdc++6`。没有隐式降级到少量番种的 Go 替代实现。

```sh
go test -race ./rules/mcr/scoring
go test ./rules/mcr/scoring -bench BenchmarkEvaluate -benchtime=1000x
```

更新上游时先校验许可证与提交，重放本地补丁，核对 `UPSTREAM.json`，运行测试并重新复核口径。部署后的一盘牌必须始终使用同一 `Profile` 与规则插件版本。
